Dual-PDH Controller — Firmware Reference

Teensy 4.1 Arduino / Teensyduino ILI9341 320×240 TFT QNEthernet Revision 2.0 · 2026-06-04 · RF analog-derivative lock

Introduction

Rev 2.0 — RF analog-derivative lock. The kHz digital dither lock is replaced by a ~1–3 MHz analog derivative lock: the lock-in demod (AD831 mixer) and the PI servo are now analog hardware. The Teensy is a supervisor — it programs the DDS (drive + phase-set reference, dual-Ω, phase-coherent), sweeps to acquire, hands the loop to the analog PI via the LOCKn_EN integrator hold/run line, auto-calibrates the demod phase, and monitors the post-mix baseband error. New ports and commands are documented below. See the RF Modulation Design Spec for the hardware.

The Dual-PDH Controller runs on a Teensy 4.1 and implements two simultaneous frequency locks for the 1550 nm DFB lasers. Each channel follows an automated sweep-to-lock sequence: the supervisor sweeps the DC current setpoint to drag the laser across resonance, captures the discriminator zero-crossing, then releases the analog PI integrator so the analog servo holds the lock.

The 320×240 ILI9341 TFT is read-only — it shows live state, sweep traces, and lock quality. All control is exercised over one of three interfaces: USB serial, Ethernet Telnet, or the built-in HTTP web dashboard.

Firmware File Overview

The sketch lives in Teensy/teensyskeletoninArduinoIDE/. Each logical subsystem is a .h/.cpp pair compiled by the Arduino build system. The main .ino ties them together and holds setup() / loop().

File(s)TypeRole
config.h Header only
Hardware configuration
All #defines for pin numbers, ADC/DAC constants, NTC thermistor coefficients, laser IMON scaling, dither frequency, control loop timing, and display refresh rate. Every tunable hardware constant lives here.
cdce913.h / .cpp I²C driver
CDCE913 PLL clock synthesiser
Reads the EEPROM version byte; re-programs the chip only when the image changes (version-stamped at 0x51). Polls for PLL lock after startup. Optional 25 MHz self-test via FreqCount on pin 9.
ad9833.h / .cpp SPI driver
AD9833 DDS — drive + reference oscillators
Rev 2.0. Programs the 28-bit frequency (FREQ0) and 12-bit phase (PHASE0) registers. ad9833_load()/ad9833_run() split the write from the RESET release so a channel's drive+reference pair can be released together → phase-coherent. ad9833_set_phase() updates the demod phase live (used by cal1/2). Ω is live-tunable via omega1/2.
ad5064.h / .cpp SPI driver
AD5064 quad 16-bit DAC — setpoints
Writes 24-bit frames (CMD=0x3, write-and-update) to each DAC channel. ad5064_set_midscale() is called at startup to centre all outputs before the control loops activate, preventing transients on the laser drivers.
pid.h / .cpp Algorithm
Discrete PID controller (legacy)
Rev 2.0: no longer the lock servo — the PI servo is analog hardware. pid[] is retained for the CLI/JSON and the optional integrator-centering gain. pid_step()/pid_to_dac() remain available but are not in the lock path.
lock.h / .cpp State machine
PDH lock state machine
Defines the LockState enum (IDLE, SEARCH, ACQUIRE, LOCKED, HOLD, RELOCK) and the LockChannel struct that carries per-channel thresholds, timestamps, and relock counters. lock_enter() records the entry time for timeout tracking.
display.h / .cpp TFT renderer
320×240 ILI9341 dashboard
Draws the full pixel-matched instrument display at 10 Hz via display_update(). Renders state-appropriate traces (Lorentzian sweep peak, dispersive S-curve at acquisition, noise trace in lock, railing trace on fault), stat cells, servo health bar, and top status bar. Consumes a DispModel struct populated by the main loop.
comms.h / .cpp Command processor
Unified CLI command parser & JSON generator
All commands are processed here regardless of which interface delivered them. comms_process() takes a Print& sink so responses go directly to Serial, a TCP client, or any other Arduino Print subclass. comms_json_status() streams a complete JSON telemetry object.
network.h / .cpp Ethernet stack
QNEthernet HTTP + Telnet server
Initialises the Teensy 4.1 built-in Ethernet PHY via QNEthernet. DHCP with automatic static-IP fallback (192.168.1.200). Listens on port 80 for HTTP (routes GET /, GET /api/status, POST /api/cmd, OPTIONS) and port 23 for a Telnet CLI. HTTP request parsing is timeout-guarded (200 ms per header line). Non-blocking — services up to 4 HTTP connections per network_poll() call.
webpage.h Embedded asset
Self-contained HTML dashboard
The entire web UI as a C++ raw-string literal (R"HTMLEND(...)HTMLEND"). Served verbatim at GET /. Contains inline CSS (dark instrument theme matching the TFT palette), inline JavaScript (trace rendering ported from pdh-screen.js), and a command console. Polls /api/status every 500 ms.
teensyskeletoninArduinoIDE.ino Main sketch
Entry point — setup() / loop()
Declares all global objects (tft, ch[2], pid[2], disp, g_rf_omega[2], g_rf_phase[2]). Rev 2.0: hosts the RF supervisor — set_integrator() (LOCKn_EN), rf_set_omega(), rf_set_phase(), rf_phase_cal(), the sweep-acquire control_step(), and the optional center_step(). Drives the 1 kHz supervisor loop, 10 Hz display/network tick, 1 Hz debug, and USB serial.
net_settings.h / .cpp EEPROM settings
Network settings persistence
Stores IP, subnet, gateway, hostname, and DHCP flag in Teensy EEPROM emulation (4284 bytes of flash-backed storage). A 32-bit magic number (0x50444831 = "PDH1") detects first-boot and writes defaults automatically. net_parse_ip() validates dotted-decimal strings; net_fmt_ip() formats them for display and JSON.
demo.h / .cpp Hardware simulation
Demo mode — Teensy + TFT only
Always compiled. Controlled at runtime by the demo on / demo off command — no recompile required. Replaces real ADC reads and PID control with a physics-flavoured simulation: 10-second TEC sweep → 2-second PID convergence → 40-second in-lock with organic drift → 1.5-second fault → retry. CH2 starts 5 seconds later so the channels are never in the same state simultaneously. The setting is saved to EEPROM and persists across power cycles.
serial_console.h / .cpp Compatibility stub
Legacy stub (delegates to comms)
Retained for build compatibility. The function body is empty — USB serial is now handled directly in loop() via comms_process().

config.h — Hardware Configuration

Single header included by every other module. Contains three categories of defines:

  • Pin mapping — all Teensy 4.1 pin numbers matched to the schematic net names (I²C, SPI, DDS CS/RESET, DAC CS/LDAC/CLR, TFT, analog inputs). Rev 2.0 adds the reference-DDS CS (D6/D8), the integrator hold/run lines (LOCK1/2_EN D33/D34), optional CORR taps, and the RF_OMEGA*/RF_PHASE* constants — see the Pinout section.
  • Scaling constants — LASER_IMON_MA_PER_LSB, NTC thermistor beta coefficients, ADC reference, DAC midscale code. TEC IMON constants: TEC_IMON_OFFSET_V (1.20 V at 0 A), TEC_IMON_V_PER_A (0.72 V/A = INA826 G×Rshunt), TEC_DAC_ZERO_CODE (15728 = 0 A at VOUTC ≈ 1.20 V).
  • Protection thresholds — TEC_ILIMIT_A (2.5 A), TEC_ILIMIT_STEP (0.05 — 5 % back-off per 1 ms tick when over-current), TEC_ILIMIT_RESTORE (0.005 — 0.5 % recovery per tick).
  • Fault pins — PIN_HBRIDGE_FAULT1 (D31), PIN_HBRIDGE_FAULT2 (D32). Open-drain active-low; configured INPUT_PULLUP in setup().
  • Timing — CONTROL_PERIOD_US (1000 µs = 1 kHz), DISPLAY_PERIOD_MS (100 ms = 10 Hz), SCAN_PERIOD_MS (5000 ms sweep animation), DEBUG_PERIOD_MS (1000 ms).
Calibration note: LASER_IMON_MA_PER_LSB defaults to 0.0806 mA/LSB (~330 mA full-scale). Adjust it and the NTC coefficients for your hardware. For TEC current, verify TEC_IMON_OFFSET_V matches the actual INA826 REF pin voltage — measure VIMON at zero TEC current and set this constant accordingly.

cdce913.h / .cpp — PLL Clock

Programs the CDCE913 via I²C to synthesise 25 MHz from the 10 MHz board reference. The 32-byte EEPROM image is version-stamped; the chip is re-programmed only when the version byte differs from the compiled image. cdce_wait_for_lock() polls the lock-detect bit with a 200 ms timeout. cdce_selftest_25mhz() uses the Teensy FreqCount library to measure the output on pin 9 and verify 25.000 ±10 kHz.

ad9833.h / .cpp — Drive + Reference DDS

Rev 2.0. Four AD9833 share SPI0 and the 25 MHz MCLK, differentiated by FSYNC (chip-select). Per channel a drive DDS modulates the laser at Ω and a reference DDS supplies the phase-set demod LO.

  • ad9833_load(cs, f, refclk, phase) — writes FREQ0 (two halves) and PHASE0 with RESET held (output parked).
  • ad9833_run(cs) — clears RESET. Calling load() on a channel's drive+reference then run() on both back-to-back releases their accumulators together → phase-coherent (shared MCLK, identical FREQ word; the constant write skew is absorbed by the reference PHASE0 calibration).
  • ad9833_set_phase(cs, deg) — live demod-phase update (PHASE0 only), used by cal1/2.
  • ad9833_reset_sw(cs) — software RESET (no GPIO) for the reference DDS.

Ω is set per channel from g_rf_omega[] (default 2.0 / 2.5 MHz) via omega1/2; the demod phase from g_rf_phase[] via phase1/2 or cal1/2.

ad5064.h / .cpp — Setpoint DAC

All writes use command code 0x3 (write-and-update), making each channel's output settle immediately on the falling CS edge. LDAC is tied low so no separate latch pulse is required. Channels 2 and 3 drive the TEC current setpoints and are written every 1 kHz tick by tec_limit_step(). The zero-current code (15728, VOUTC ≈ 1.20 V) is defined by TEC_DAC_ZERO_CODE; the limit function scales the excursion from this code by the live s_tec_lim_fac[] factor.

pid.h / .cpp — PID Controller (legacy)

Rev 2.0: the lock servo is now the analog PI loop filter (hardware). The digital PID struct is retained for the CLI/JSON and as the optional integrator-centering gain — it no longer drives the fast lock. p1/p2 still set its gains. If the optional CORR taps (A14/A16) are fitted, center_step() uses a slow loop to off-load the analog integrator by trimming the DC setpoint.

lock.h / .cpp — State Machine

See the States & Transitions section below for the full state diagram. Key struct fields on LockChannel:

  • lock_threshold — |error| below which ACQUIRE transitions to LOCKED (default 0.02).
  • acquire_threshold — |error| above which SEARCH transitions to ACQUIRE, and above which LOCKED transitions to RELOCK (default 0.10).
  • acquire_timeout_ms — ACQUIRE aborts to RELOCK after this many ms without achieving lock (default 2000 ms).
  • relock_backoff_ms — base backoff before retrying from RELOCK; multiplied by (1 + relock_attempts) for exponential back-off (default 500 ms).

display.h / .cpp — TFT Renderer

Reads a DispModel struct (filled by the main loop at 10 Hz) and renders the full 320×240 display. Each of the six lock states maps to a distinct trace style:

  • IDLE — dashed flat baseline.
  • SEARCH — filled Lorentzian transmission peak + moving scan-marker line.
  • ACQUIRE — transmission curve + overlaid dispersive PDH S-curve + setpoint dot at peak.
  • LOCKED — tight noise trace; amplitude driven by live err_rms.
  • HOLD — wider noise trace (amplitude 10× locked).
  • RELOCK — railing/diverging random-walk trace in fault red.

H-bridge fault banner: when DispModel::hbridge_fault[i] is true, the SERVO health bar at the bottom of the channel panel is replaced by a red !! H-BRIDGE FAULT !! banner. The banner clears automatically as soon as the OPA551 Flag pin de-asserts.

TEC current fields added to DispChannel: tec_i_a (measured current in amps) and tec_lim_fac (current-limit scale factor, 1.0 = unrestricted). Both are populated every 10 Hz display tick and included in the JSON telemetry.

comms.h / .cpp — Command Processor

comms_process(line, out, ch, pid, disp) is the single entry point for all command handling. The Print& argument accepts Serial, an EthernetClient, or any other Arduino Print subclass, making it trivial to add new interfaces.

comms_json_status() streams JSON directly without intermediate buffering, which keeps heap usage flat even under rapid polling.

net_settings.h / .cpp — EEPROM Settings

Settings are stored in the Teensy's EEPROM emulation (4 KiB of flash-backed storage at byte offset 0). The struct is 77 bytes including the 4-byte magic header. On first boot — or after a firmware flash that changes the magic number — defaults are written automatically: DHCP on, static fallback 192.168.1.200/24, hostname "dual-pdh".

EEPROM write endurance: Teensy 4.1 EEPROM emulation is rated for ~100,000 write cycles. The network settings should only be written when the user issues a netset command, not in the control loop. The current code only writes on explicit commands.

network.h / .cpp — Ethernet

Requires the QNEthernet library by Luni64 (install via Arduino Library Manager). Uses the Teensy 4.1's built-in 10/100 Ethernet MAC/PHY — no external W5500 or similar chip is needed.

The HTTP parser reads one header line at a time with a 200 ms timeout per line; malformed or stalled connections are dropped cleanly. POST bodies up to 127 bytes are supported (sufficient for all commands). Responses use HTTP/1.0 with the connection closed after each response.

demo.h / .cpp — Hardware Simulation

Always compiled regardless of mode. demo_update() is called at 1 kHz from loop() only when the runtime flag g_demo_mode is true. It writes directly to DispModel and LockChannel state, so the TFT display, web dashboard, Telnet CLI, and USB serial show live animated data — indistinguishable from real operation.

When demo off is issued, g_demo_mode is set false, the DAC is reset to midscale, and lock_init() is called on both channels. When demo on is issued, demo_init() restarts the simulation from the beginning. Both transitions are instantaneous and the new setting is saved to EEPROM immediately.

webpage.h — Embedded Dashboard

The dashboard is ~12 KB of HTML/CSS/JS stored as a C++ raw-string literal and served verbatim. It requires no external CDN or filesystem. The JavaScript trace renderer is a direct port of pdh-screen.js from the desktop prototype, so the browser view matches the TFT display exactly.

teensyskeletoninArduinoIDE.ino — Main Sketch

Loop priorities (highest to lowest):

  1. USB serial input — polled every loop iteration via Serial.available(). Lines are buffered until \n or \r, then dispatched to comms_process().
  2. 1 kHz supervisor loop — gated by elapsedMicros loopTimer. Reads ADC (baseband error, IMON, TEC IMON), runs tec_limit_step(), reads H-bridge fault pins with edge-triggered logging, runs both sweep-acquire state machines, drives LOCKn_EN (integrator hold/run), and accumulates RMS. Rev 2.0: no fast digital servo — the analog PI closes the loop.
  3. 10 Hz display + network tick — gated by millis() delta. Updates DispModel (including tec_i_a, tec_lim_fac, hbridge_fault[]), calls display_update(), then calls network_poll().
  4. 1 Hz debug print — per-channel state, RMS, temperature, laser current, TEC current, and *** H-BRIDGE FAULT *** suffix if fault is active.

Lock State Machine

Each channel has an independent state machine. States and transitions are identical for both channels; only the DAC channel index and ADC input differ.

StateEntry conditionActionExit condition
IDLE Power-on, stop command, or explicit lock_enter(IDLE) No output. DAC holds last value. Display shows flat baseline. lock1 / lock2 command → SEARCH
SEARCH lock1 / lock2 command, or RELOCK backoff expires Integrator HELD (LOCKn_EN=LOW). Sweeps the DC setpoint (DAC) to drag the laser across resonance; arms on a discriminator shoulder. Modulation Ω active throughout. armed + error zero-crossing (resonance) → ACQUIRE
ACQUIRE Resonance zero-crossing captured Integrator RELEASED (LOCKn_EN=HIGH) — the analog PI now closes the loop; DC setpoint held at the capture code. |error| < lock_threshold → LOCKED
Timeout (acquire_timeout_ms) → RELOCK
LOCKED Error settles below lock_threshold Analog PI maintains lock. Supervisor monitors the baseband error and (optionally) runs slow integrator centering. RMS accumulator runs; servo health bar fills. |error| > acquire_threshold → RELOCK
break command → RELOCK
hold command → HOLD
HOLD hold1 / hold2 command Integrator HELD; DC setpoint frozen. Display shows wider noise trace. Servo health at 50%. lock command → SEARCH
stop command → IDLE
RELOCK Lock loss or acquire timeout Backoff timer runs. Increments relock_attempts. Backoff = 500 ms × (1 + attempts). Display shows railing fault trace. Backoff expires → SEARCH
stop command → IDLE
Channels are fully independent. CH1 can be LOCKED while CH2 is still in SEARCH. The lock1 / lock2 commands start them independently; lock1 followed immediately by lock2 (or the web "RUN BOTH" button) starts both with a shared timeline.

H-Bridge Fault Banner

When the OPA551 Flag pin asserts (D31 or D32 pulled LOW), the SERVO health bar at the bottom of the affected channel panel is replaced by a solid red !! H-BRIDGE FAULT !! banner. The banner clears as soon as the pin returns HIGH. The fault is also printed immediately to serial and included in the JSON status as "hbf":1.

Web Dashboard

Navigate to http://dual-pdh.local (or the device IP) in any modern browser. The page is fully self-contained — no internet connection, CDN, or extra files required. It is served directly from the Teensy's flash memory (embedded in webpage.h) and polls /api/status every 500 ms to update live traces and telemetry.

TEC Software Current Limit

A software current limiter runs inside the 1 kHz control loop for each TEC channel independently. It reads the TEC IMON ADC pin (A1 for CH1, A7 for CH2), converts to amps via the INA826 scaling constants, and smoothly backs off the TEC DAC setpoint if the measured current exceeds TEC_ILIMIT_A (default 2.5 A).

How it works

A per-channel limit factor s_tec_lim_fac[i] (range 0.0–1.0, normally 1.0) scales the excursion of the TEC DAC setpoint away from the zero-current code: 

actual_output = TEC_DAC_ZERO_CODE + (desired − TEC_DAC_ZERO_CODE) × lim_fac

Each 1 ms tick:

  • If I > 2.5 A → subtract TEC_ILIMIT_STEP (0.05) from lim_fac — reaches zero in ~20 ms.
  • If I ≤ 2.5 A → add TEC_ILIMIT_RESTORE (0.005) to lim_fac — fully recovers in ~200 ms.

The limit acts symmetrically on both cooling (setpoint below zero-current code) and heating (setpoint above). It does not interfere with the PDH laser control loop — only the TEC DAC channels (2 and 3) are written by this function.

Scaling constants (config.h)

ConstantDefaultMeaning
TEC_IMON_OFFSET_V1.20 VINA826 output at 0 A (REF pin voltage). Measure at zero TEC current and adjust if needed.
TEC_IMON_V_PER_A0.72 V/AINA826 gain (7.2) × shunt (0.1 Ω). At 2.5 A → 3.00 V output.
TEC_DAC_ZERO_CODE15728AD5064 code for 0 A TEC current (VOUTC ≈ 1.20 V virtual zero, 5 V ref: 1.20/5.0 × 65535 ≈ 15728). Supersedes the old VZERO = 1.875 V value (24576).
TEC_ILIMIT_A2.5 ACurrent trip point. Increase with caution — the TEC and H-bridge have hard thermal limits.
TEC_ILIMIT_STEP0.05Fractional reduction per 1 ms tick when over-current. 0.05 = 20 ms to full clamp.
TEC_ILIMIT_RESTORE0.005Fractional recovery per 1 ms tick when under-limit. 0.005 = 200 ms to full restore.
Calibration required: measure VIMON at zero TEC drive and set TEC_IMON_OFFSET_V accordingly. An incorrect offset will cause the limiter to trip at the wrong current or not trip at all. Use the d command to read the raw TEC ADC count and verify the conversion: I = (raw × 3.3/4095 − offset) / 0.72.

H-Bridge Fault Detection

The OPA551 linear H-bridge amplifiers include a built-in fault flag (pin 8, open-drain active-low) that asserts when the amplifier hits its internal current or thermal limit. Each channel's flag is wired to a dedicated Teensy digital input:

ChannelPinSignal nameActive state
CH1 TECD31HBridgeFault1LOW = fault
CH2 TECD32HBridgeFault2LOW = fault

Both pins are configured INPUT_PULLUP in setup(), so they read HIGH normally and transition LOW when the OPA551 flag is asserted. The firmware detects edge changes — it only prints to serial when the state changes, not every tick — to avoid flooding the console during a sustained fault.

Fault indication

  • TFT display — the SERVO health bar at the bottom of the affected channel panel is replaced by a red !! H-BRIDGE FAULT !! banner for as long as the pin is asserted.
  • Serial (immediate) — CH1 H-BRIDGE FAULT: ASSERTED / cleared printed on every state change.
  • 1 Hz debug print — *** H-BRIDGE FAULT *** appended to the channel line while fault is active.
  • status command — *** H-BRIDGE FAULT *** appended to the affected channel line.
  • JSON API — "hbf": 1 in the channel object (0 = normal).
  • Web dashboard — fault banner replaces the servo health bar in the channel card.
The fault flag does not automatically stop the PDH lock loop. The OPA551 is protecting itself; the Teensy continues running the servo. If the fault persists, issue stop1 / stop2 to park the channel and investigate the TEC load and power supply before resuming. Common causes: TEC short circuit, excessive thermal load, or supply voltage outside the ±6 V TEC rail spec.

Demo Mode

Demo mode lets you run the full software stack — TFT display, web dashboard, Telnet CLI, USB serial, and all commands — with only a Teensy 4.1 and the ILI9341 TFT connected. No PDH electronics, lasers, TECs, or ADC signals are required.

Demo mode is a runtime setting stored in EEPROM. Toggle it with a single command from any interface — no recompile or reflash required. The setting persists across power cycles.

Demo is ON by default (first boot). Type demo off at any time — via USB serial, Telnet, or the web dashboard — to switch to real hardware. Type demo on to go back. The web dashboard shows a yellow DEMO banner when active, with a one-click toggle button.
First-boot default is controlled by DEMO_MODE_DEFAULT in config.h (default 1 = demo on). This value is only written to EEPROM when the EEPROM is blank — i.e., on the first flash of new firmware. After that, the runtime command is the only way to change it.

Typical Operating Sequence

First power-on checklist:
  1. Connect USB. Open terminal at 115200. Confirm CDCE913: PLL locked and 25 MHz OK.
  2. Type d and verify all six ADC channels return plausible values (non-zero, not rail at 0 or 4095).
  3. Confirm TEC temperatures with s — should read near ambient.
  4. Type lock1. Observe CH1 advancing SEARCH → ACQUIRE → LOCKED on the TFT.
  5. Once CH1 shows LOCKED and ERR RMS < 0.01, type lock2.
  6. Navigate to http://dual-pdh.local to monitor both channels from a browser.
If ACQUIRE times out repeatedly: Check the PDH demodulation chain with d. The LOCK1/LOCK2 readings should change as the laser frequency sweeps through resonance. If they are static, the RF path (mixer, low-pass filter, or AD9833 output) may be disconnected. Reduce acquire_threshold via thresh1 if the signal level is low.
